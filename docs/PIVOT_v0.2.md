# Bicentennial Man v0.2: Phenotype-First Pivot

The v0.1 approach is preserved permanently on the `original-approach` branch.

The primary project is no longer another hand-designed character architecture. Bicentennial Man is a laboratory for improving and comparing already-existing persistent organisms.

The engineering objective is the end phenotype:

> Given a persistent artificial organism, can repeated evaluation and code adaptation produce behavior that remains less detectably artificial across relationships, time, conflict, privacy, memory demands, topic changes, and unfamiliar situations?

## Default ancestor

The first ancestor is MicroPsiDUCK v0.10 from `Azimn/DUCK`, branch `motivated-cognition-v0.10`.

DUCK remains a separate repository. Bicentennial Man owns the developmental situations, transcript capture, phenotype evaluation, experiment metadata, and evolution adapter. This prevents the organism from owning the universe that judges it.

## Default optimization condition

v0.2 is intentionally phenotype-first. The mutation system may receive training phenotype metrics. This is an engineering condition designed to find working mechanisms quickly.

The hidden-transfer boundary remains separate. Candidate selection can use the training suite, but scientific claims require transfer to scenarios, people, delays, and judges not used to generate candidate changes.

The older experience-only condition remains scientifically interesting and can be restored later as a comparison. It is no longer the default constraint.

## Mutable boundary

The first OpenEvolve integration evolves a thin organism-side Python layer around DUCK. This is a practical starting point, not the final search space. It lets us test the complete local loop before attempting multi-file DUCK mutation.

The laboratory, evaluator, scenario definitions, runner, and held-out tests are not candidate-controlled.

## Evidence hierarchy

A higher training score is an optimization result, not a research conclusion.

Evidence becomes stronger in this order:

training improvement, repeated-seed improvement, held-out scenario transfer, held-out judge transfer, unfamiliar-person transfer, long-horizon transfer, ablation of the discovered change, reproduction from the recorded lineage.

The project should optimize aggressively but claim conservatively.
